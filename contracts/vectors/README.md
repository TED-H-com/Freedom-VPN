# Contract vectors

Golden vectors shared by every implementation (Go, TypeScript, tests). They
are generated by `contracts/internal/cmd/contractsgen` from fixed inputs and
the TEST ONLY seeds, and checked by `contracts/vectors_test.go` (Go) and
[`contracts/ts/verify-vectors.ts`](../ts/verify-vectors.ts) (TypeScript).
Regenerate with `make -f mk/contracts.mk contracts-generate`; never edit them
by hand.

> All seeds and keys here are **TEST ONLY - NOT A SECRET**. Each seed is the
> SHA-256 of the UTF-8 string
> `TEST ONLY - NOT A SECRET: fvpn contracts <label> test key`. Never add these
> keys to a production trust store.

## Signing vector fields

| Field | Meaning |
|---|---|
| `seed_hex`, `public_key_b64`, `key_id`, `purpose` | the TEST ONLY Ed25519 key |
| `signed` | the signed object |
| `canonical_signed` | its RFC 8785 canonical JSON: the exact signature input |
| `canonical_signed_sha256` | SHA-256 hex of `canonical_signed` |
| `signature_b64` | Ed25519 signature (standard base64 with padding). Ed25519 is deterministic, so re-signing must reproduce it byte for byte |
| `envelope` | `{"signed": ..., "signatures": [{"key_id", "algorithm": "ed25519", "signature_b64"}]}` |
| `envelope_sha256` | SHA-256 hex of the canonical envelope (for a manifest this is `manifest_sha256`) |
| `verify_at` | an instant inside the test keys' validity window |

## Reusing the vectors from TypeScript

`contracts/ts/verify-vectors.ts` is a dependency-free example that Node 24 runs
directly (`node contracts/ts/verify-vectors.ts`). The pieces a client needs:

1. **Canonical JSON for the subset.** Parse the original bytes with
   `parseStrictJSON` from `strict-json.ts`, reject any
   number that is not `Number.isSafeInteger` (or is `-0`), sort object keys
   with the default `Array.prototype.sort()` (it compares UTF-16 code units,
   exactly as RFC 8785 requires), and emit strings with `JSON.stringify` (its
   escaping is the RFC 8785 escaping). Compare the result with `canonical`.
2. **Hashes.** Remove the named top-level member (`payload_sha256` or
   `payload_hash`), canonicalize, then SHA-256 the UTF-8 bytes
   (`crypto.subtle.digest` in browsers, `node:crypto` in Node).
3. **Signatures.** Canonicalize `envelope.signed`, then verify `signature_b64`
   with the Ed25519 public key (WebCrypto `Ed25519` or `node:crypto`).
4. **Decimal strings.** Keep them as strings; validate with
   `/^(0|[1-9][0-9]*)$/`, at most 20 characters and
   `BigInt(s) <= 18446744073709551615n`. Never convert to `Number`.

`JSON.parse` silently accepts duplicate keys, lone surrogates and integers
beyond 2^53, so code that **accepts untrusted documents for hashing or
verification** needs a strict parser that rejects every entry of `rejects` in
`canonical-json.json`; the Go implementation is `pkg/canonjson`. The independent
TypeScript `strict-json.ts` checks all reject classes, a 1 MiB byte cap and depth
256, including the depth-257 reject and keys differing past the BMP. A
TypeScript test suite can load the files directly, for example:

```ts
import vectors from "../../contracts/vectors/canonical-json.json" with { type: "json" };
for (const c of vectors.cases) {
  const input = Uint8Array.from(atob(c.input_b64), (ch) => ch.charCodeAt(0));
  expect(canonicalize(parseStrictJSON(input))).toBe(c.canonical);
}
```

## Resolver reference (revision 5)

Verify the desired-state signature first, then fetch the referenced document
using node mTLS. Hash the **exact received bytes** (including no extra newline),
compare their length and digest to signed `size_bytes`/`content_sha256`, and only
then parse/apply. Go and TypeScript check the new vector against the committed
canonical document; changing the reference or probe target invalidates its
signature. The original desired-state vectors remain byte-for-byte unchanged.
