## D-146 design

Keep every production MTU unchanged. The lab tunnel stays at 1420; the native
row's tunnel stays at its configured value. Use a **1160-byte IPv4 TCP MSS
ceiling**, only when an existing MSS option exceeds it and SYN is set (including
SYN-ACK). Missing MSS options and smaller advertisements are untouched.

For the standard WireGuard UDP transport, outer overhead is IPv4 20 or IPv6 40,
UDP 8, WireGuard data header 16 and authentication tag 16. Plaintext is padded
to a multiple of 16. Thus the maximum inner packet at a 1280-byte receiving link
is min(tunnel MTU, floor((1280 − outer IP − 8 − 32) / 16) × 16):
IPv4 permits 1216 bytes (MSS 1176); IPv6 permits 1200 (MSS 1160). Choose the
smaller, 1160, for both. At inner length 1200, outer lengths are 1260 / 1280.
This bounds padding as well as headers; simply subtracting 60 from 1280 would
miss padding. Standard transport headers are assumed; extra encapsulations or
IPv6 extension headers need their own budget and are not claimed here.

MSS excludes the fixed inner IPv4 20 and TCP 20 headers. A compliant sender
subtracts its actual TCP/IP options from data: timestamps (12 bytes) give
1148 data + 32 TCP + 20 IPv4 = 1200; maximum TCP options (40) give
1120 + 60 + 20 = 1200. IP options likewise reduce data. See
[WireGuard transport format](https://www.wireguard.com/protocol/) and
[RFC 6691 §2](https://www.rfc-editor.org/rfc/rfc6691.html#section-2).

Add one non-verdict clamp immediately before each admitted address's general
upload accept and one immediately before its general download accept. Both
name the existing interface pair and the same IPv4 device address as that
accept. The member SYN limits remote downloads; the remote SYN-ACK limits
member uploads. Existing admission, deny, DNS, counter and classification
rules retain their order and expressions. The clamps have no counter or
priority statement. Earlier DNS service accepts remain DNS service; probe
accepts and fail-closed probe baselines are unchanged and have no clamp.

Receive-only member-underlay MTU 1280 with no PTB is a separate fixture from
[netlab 18's exit-link measurement](G2-f802-mtu1280-2026-10-31.md). Capture
unchanged-main failures, then verify 64,064 bytes in each TCP direction, MSS
at both endpoints, exact forwarded IP-byte accounting and member class use.
UDP remains failed on the same link; no QUIC client is available. The lab
proves fixed IPv4 underlay only; members owns IPv6-underlay and native reruns.

## D-147 design

Before the three download source-deny drops, after membership and
established/related guards and the existing DNS accepts, add three per-address
accepts: source in resolver_v4, denied_v4, or host_v4; destination exactly the
admitted IPv4 address; conntrack RELATED; ICMP type 3/code 4. Each uses the
existing device download counter and assigned priority. Overlapping sets
cannot double-count because the first matching rule accepts.

All three sets qualify: D-147 is about the outer source of a path error, not
permission to originate a member connection to that source. This includes a
resolver address acting as a path hop and a LAN router present in both host_v4
and denied_v4. The exception grants no upload reachability, probe exception,
unsolicited download, other ICMP code/type, or IPv6 forwarding. RELATED is
required in the exception itself. Current membership still expires in the
kernel's allowed_v4 elements. These rules do not change per-binding deadlines.

An isolated uplink-side private router with a smaller outgoing MTU will
produce genuine fragmentation-needed for a TCP upload. Retain main's ctdenyd
drop, then prove PMTU learning and completion, exact error-byte usage and
priority, plus continued time-exceeded and unsolicited-error drops. Run the
existing isolation and consumer suites unchanged.
