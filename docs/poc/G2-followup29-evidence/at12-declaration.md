## Code candidates, before measurement

`scenario_at12_test.go` applies generation 12, then reads `before`, runs 17 deny cases and target captures, then reads `mid`. Its assertion compares the same device's absolute upload bytes. `flushConntrack` flushes the node's tracking table; it does not destroy sockets in `fv-a1`. Counter objects survive Apply.

1. **A deny probe reaches a member counter before a drop.** In `node/enforce/render_nft.go`, IPv6, INVALID, missing admission, bad resolver use, denied destination and host destination drops precede the per-device upload rule. The counter and `accept` are on that same rule. Input and off-path drops never enter that rule. `ctdeny`, `ctin`, `ctbadns`, etc. are separate diagnostic objects; `Samples` only joins `u_<device>` for upload. A later foreign hook/tc drop is theoretically possible after forward admission; collect live rules and forwarding copies to distinguish it. A missing deny match or wrong hook/interface is a product candidate, not excluded by static ordering alone.
2. **Other traffic on `fv-a1`.** AT10 leaves an established TCP echo socket with data sent while revoked; its cleanup sends SIGTERM, without checking that kernel queues have drained. R19 likewise stops a persistent stream after denying its destination. Re-admission in AT11/12 can allow residual retransmissions/FIN/ACK/RST or resulting ICMP. Probe Python uses numeric IPs (no lookup), local files and subprocesses; `tcp_connect` sends a SYN and closes, with no application data. `ping` emits one default-size echo request. IPv4-mapped AT11 connects use `IPV6_V6ONLY`; capture will decide whether any actually used the IPv4 path. WireGuard outer UDP, ARP and IPv6 neighbour traffic can exist, but are not inner IPv4 upload samples.
3. **Sampling.** `readCounters` writes a model file and invokes `fvpn-netlab counters`, which runs one `nft -j list table inet fvpn`, parses exact integer values, and joins samples from that same counter map. `sampleBytes` selects the first exact device/direction, returning zero if absent. No delta/reset compensation, float conversion or summation occurs here. A missing/duplicated sample or a packet concurrent with a read must be checked against retained documents and read brackets. Reads are not an atomic snapshot of all packets across all CPUs; an observed change still needs packet attribution.

## Exact 97-byte size candidates (inner IP length)

These are arithmetic possibilities, not observations. Actual header options, payload sizes and packet grouping must come from capture.

| Candidate | Sizes that make 97, or why they cannot |
|---|---|
| AT12 TCP deny connects | Usual IPv4 SYN 60; retransmitted SYN 60; no application payload. Any sum of these even lengths cannot be 97. Bare ACK/RST 40 or timestamp ACK/FIN 52 are also even. |
| AT12 ICMP echo / raw loopback | Default IPv4 echo 84; raw4 is 20+8+2 = 30. These, with SYN/ACK/RST sizes above, cannot total odd 97. Rogue/spoof sources also do not select devA1's counter. |
| Earlier stream TCP data | One timestamp TCP segment: 20+32+45 = 97 (45 pending application bytes). Without timestamps: 20+20+57 = 97. A 5-byte token with timestamps (57) plus a bare RST (40) also totals 97. A 3-byte token (55) plus a 42-byte segment is arithmetically possible, but needs a nonstandard/options/payload explanation. |
| Earlier TCP plus UDP | Timestamp TCP with 12 data bytes (64) plus UDP with a five-byte token (33) = 97; TCP with 13 (65) plus UDP with four (32) = 97. The stream can coalesce several queued tokens after revoke. |
| Earlier ICMP error | IPv4 ICMP error is 20+8+quoted packet. A 69-byte quote gives 97; a complete small UDP quote gives 59/60/61 for three/four/five-byte stream tokens and needs additional packets totalling 38/37/36 respectively. An error cannot be identified from length alone. |
| Probe tooling / DNS | No DNS lookup is requested; the explicit DNS phase is after `mid`. A hypothetical 69-byte UDP payload gives 97, but no deny-phase helper sends it. DNS fixture is 27 bytes: IPv4 UDP length 55, in a separate namespace counter if requested. |
| Sampling artifact | No required wire sizes: a wrong sample could show an arbitrary difference. Match sample bytes/packets to the named counter and all observed forwarding copies before attributing it. |

## Measurement and decision rule

At most three full-suite runs; each is a retained measurement, never a retry for green. Start all-interface AF_PACKET metadata recorders in `fv-a1`, the node and responder before the first live scenario. They survive the suite's tcpdump cleanup. Keep kernel timestamps, protocol/header lengths, sequence/ack/flags, packet IDs and interface/direction; publish no payload, MAC address or raw pcap. Require zero capture drops and complete socket delivery accounting. Preserve every `before`/`mid` sample and adjacent entire nft ruleset with handles and all existing named/per-rule counters. Do not add counters or alter any production rule for F28-01.

Each run requires an exclusive reservation, a 60-second settling wait, no competing suite/test process, and six current `vmstat 5 7` intervals with r ≤ 3 and idle ≥ 80. Repeat the quiet check after topology startup. Record all admission attempts and release promptly. The AT12 assertion is unchanged. A nonzero delta stays FAIL unless every excluded byte is proved to be an earlier flow; no tolerance, sleep-for-green or counter reset is authorized by this declaration. Product fixes follow evidence and require a failing regression and D-133 cost if serving changes. Unattributed results keep the assertion and finding open.
