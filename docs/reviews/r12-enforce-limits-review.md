## What Held

1. **Verifier table boundary and concatenation tuple validation (`node/enforce/verify.go`, `node/enforce/parse_nft.go`, `docs/poc/G2-netlab.md`):** By `AGENTS.md §4` and `Apply` (`nft -j list table inet fvpn`), `VerifyServing` inspects `table inet fvpn`. A `/0` prefix or range inside `@probe_dst_v4` (`0.0.0.0/0 . tcp . 443`) was already rejected by `parseConcatDest` (`hasPrefixOrRange` and `netip.ParseAddr` on the address cell). *(The 10 in-table verifier gaps in `H-1` were closed in netlab `#172`.)*
2. **Revocation rule ordering and conntrack deletion (`node/enforce/render_nft.go`, `node/enforce/apply.go`):** In both `serving.nft` and `probe-serving.nft`, upload `iifname "fv-fh" ip saddr != @allowed_v4 counter name "ctunauth" drop` and download `oifname "fv-fh" ip daddr != @allowed_v4 counter name "ctunauth" drop` precede all member established/related, DNS, and upload accepts (`probe_down` when `Probe != nil` is guarded by `ip daddr @probe_v4`, which cannot overlap `@allowed_v4`). ` flush set inet fvpn allowed_v4` removes a revoked member atomically in the `nft -f` transaction before `deleteConntrack` runs (`conntrack -D -s <ip>` and `conntrack -D -d <ip>`, deleting all outbound UDP flows across churning source ports). *(The `Samples` zero-metadata leak and `ConntrackDeleteError` counter drop in `M-3` were closed in netlab `#172`; pending conntrack retry and `ISOLATION_POLICY_INVALID` reporting were added in agent `#166`.)*
3. **Deny-list boundaries and non-53 resolver drop (`node/enforce/prefixes.go`, `node/enforce/render_nft.go`):** `SpecDeniedV4()` covers the 16 merged non-globally-reachable IANA IPv4 Special-Purpose blocks plus multicast (`224.0.0.0/4`), intentionally denying `192.0.0.9/32` and `192.0.0.10/32` via their parent `192.0.0.0/24` block (`Globally Reachable: False`), while `ExtraDeniedV4` unions caller-supplied public on-link uplink prefixes and gateways into `@denied_v4`.
   - **§3 resolver non-53 note (`closed (#172)`):** The review noted that in serving mode `Render` accepted member TCP/UDP port 53 to `@resolver_v4` and dropped port 53 to non-resolvers, but lacked `iifname "fv-fh" ip daddr @resolver_v4 counter name "ctbadns" drop` for non-53 ports when a resolver used a public IP outside `@denied_v4`/`@host_v4`. Netlab `#172` added `iifname <in> ip daddr @resolver_v4 counter name "ctbadns" drop` immediately after the TCP/UDP port-53 resolver rules in `Render` and required `hasBadDNSDrop` in `VerifyServing` whenever `len(m.Resolvers) > 0` (with or without a probe).
4. **Limiter keying, IPv6 `/64` prefix masking, `Retry-After` ceiling, and metric cardinality (`internal/httpapi/middleware.go`, `pkg/apierr/apierr.go`):** `connectionRateKey` keys IPv4 per `/32` and IPv6 per `/64` strictly from `r.RemoteAddr`, ceiling sub-second waits to integer `Retry-After` seconds, and bounding `fvpn_control_rate_limited_total` to at most $7 \times 3 = 21$ `(class, limiter)` series. Two mTLS nodes behind one NAT IP get independent post-auth per-node buckets (`heartbeat`, `lease`, `usage`, `agent`) while sharing the per-class `IngressRate` (`30/s`, burst `60`) address bucket. *(Per-class ingress tables, separate `anonymous` class table, mTLS client-certificate check before table insert, O(1) LRU tail eviction, and the concurrency gate metric in `M-2` and `L-1` were closed in control `#169`.)*
   - **§4 reverse-proxy keying note (control follow-up 18, open at this snapshot):** Because `connectionRateKey` reads `r.RemoteAddr` and ignores `X-Forwarded-For`, `Forwarded`, and `X-Real-IP`, placing `fvpn-control` behind a reverse proxy that rewrites TCP source addresses causes unauthenticated clients behind that proxy to share one proxy-IP bucket unless `fvpn-control` terminates TLS directly or configures trusted-proxy CIDRs (tracked in control follow-up 18 `trusted_proxies`).
5. **Request-body byte caps and `canonjson.MaxBytes` signed-document bound (`internal/httpapi/middleware.go`, `pkg/canonjson/canonjson.go`):** Rate-limit tokens and concurrency slots are acquired before reading the body; `io.ReadAll(io.LimitReader(r.Body, bodyLimit+1))` enforces exact byte caps (`64 KiB` `browser`, `256 KiB` `agent`/`heartbeat`/`lease`/`anonymous` code defaults, `8 MiB` `usage`, `0 B` `ConsumeAgentBootstrap`) including chunked streams without `Content-Length`, while `canonjson.MaxBytes` (`1 MiB`) remains unchanged on `envelope.Sign`/`Verify` and per-event usage hashing. *(Streaming `canonjson`-subset enforcement above `1 MiB` in `M-1` was closed in control `#169`.)*
6. **D-063 issuer URL/address validation and agent re-check (`node/updater/probe_addresses.go`, `node/agent/probeexc.go`):** `readProbeAgentConfig` enforces a `1 MiB` size cap (`1,048,577` bytes refused with `agent_config_unavailable`); `probeURLHost` refuses `control_url`/`result_url` with userinfo (`control_addresses_unavailable`), strips ports before resolving all DNS answers, and unmaps IPv4-mapped IPv6 addresses (`::ffff:...`) on both interfaces and DNS answers; and `fvpn-agent` re-verifies challenge freshness, identity, `100.64.0.0/10` source, `Datapath.SNAT`, `Resolvers`, `SpecDeniedV4()`, and `ExtraDeniedV4` before installing the probe exception. *(Empty interface-list refusal, non-symlink regular-file verification on `agent.json`, and challenge/journal/health/observation recording of `probe_omitted` in `H-2` were closed in updater `#168` and agent `#171`.)*
7. **Pre-result seeding incarnation guard, revoked `last_good`, and `last_good` immutability (`internal/fleetupdate/serving.go`):** `observeTx` never updates `nodes.last_good_release_id` from a heartbeat (only accepted `SubmitResult` receipts do), `NodeVersionView` computes `RecoveryRequired` from whether the recorded `last_good_release_id` is in `revoked_release_ids`, and a job target recorded for a different incarnation cannot seed `nodes.current_release_id`. *(Binding pre-result seeding and `unexpected_release` audits to the reported `jobID`, requiring an issued intent `j.issued != nil`, and requiring `last_good_release_id` agreement before seeding `current_release_id` in `H-3` were closed in fleet-update `#167`.)*

## Detailed Review Notes

### High Findings

#### `H-1` — `VerifyServing` accepted out-of-model forwarding rulesets (`closed (#172)`)

- **Where:** `node/enforce/verify.go:47-91`, `node/enforce/verify.go:150-258`, `node/enforce/verify.go:307-310`, `node/enforce/verify.go:555-572`, `node/enforce/verify.go:643-661`, `node/enforce/parse_nft.go:107-135`, `node/enforce/parse_nft.go:190-213`, `node/enforce/parse_nft.go:545-555`
- **Problem:** Ten classes of ruleset drift or renderer/parser gaps passed `VerifyServing(rs, m)`:
  1. `ct state related` accept at index 0 of `forward` (`mentionsEstablished` only matched `"established"`, not `"related"`).
  2. `meta mark` or arbitrary non-probe `accept` before `@allowed_v4` drop (`other` accepts were rejected only when `baseline == true`).
  3. Unconditional `accept` right after upload `ip saddr != @allowed_v4 drop` (bypassing rogue-DNS, `@denied_v4`, `@host_v4`, and per-device counters/QoS).
  4. Missing download `ip daddr != @allowed_v4 drop` (`checkForwardOrder` used a single boolean `seenAllowDrop` satisfied by the upload drop alone).
  5. Missing `@denied_v4` and `@host_v4` drop rules when `m.Probe == nil` (`hasDeniedDrop` and `hasHostDrop` were checked only when `m.Probe != nil`).
  6. Tainted prefix (`0.0.0.0/0`) in `@resolver_v4` when `m.Probe == nil` (`verifyResolverSet` returned `nil` when `m.Probe == nil`).
  7. Extra base chains in `inet fvpn` such as a `prerouting` DNAT chain.
  8. `accept` rule before `drop` in `inet fvpn input`.
  9. `flags interval` on `@allowed_v4` (`parseSet` ignored `m.Set.Flags`).
  10. Duplicate chain names across families (`ParseRuleset` keyed `rs.Chains` by `m.Chain.Name` alone, allowing `chain ip fvpn forward` with `policy drop` to mask `chain inet fvpn forward` with `policy accept`).
- **Resolution (`#172`):** `VerifyServing` (`node/enforce/verify.go`, `node/enforce/parse_nft.go`) now requires every `accept` rule in `forward` to be a verified serving rule (member DNS to `@resolver_v4:53` after upload `@allowed_v4` drop, per-device upload/download accept after `@denied_v4` and `@host_v4` drops, or download `ct state established,related` after download `@allowed_v4` drop) or a verified probe accept when `m.Probe != nil`; treats `ct state related` as established; tracks upload and download `@allowed_v4` drops separately; checks `@resolver_v4`, `hasDeniedDrop`, `hasHostDrop`, and `hasBadDNSDrop` (non-53 drop to `@resolver_v4`) with or without a probe; rejects chains outside `{forward, input, output, postrouting}` and keys chains by `(family, table, name)` rejecting duplicates; rejects `input` accepts before the member/CGNAT drops; and rejects `interval` flags on `allowed_v4`, `probe_v4`, `probe_dst_v4`, and `resolver_v4`. Adopted proof: `TestReviewR12_Q1_VerifierAcceptsOutOfModelForwarding` in `node/enforce/followup7_review_test.go`.

#### `H-2` — D-063 issuer address validation accepted an empty node interface list, followed symlinks on `agent.json`, and left probe omission unrecorded (`closed (#168, #171)`)

- **Where:** `node/updater/probe_addresses.go:51-65`, `node/updater/probe_addresses.go:96-116`, `node/updater/probe_addresses.go:181-196`, `node/updater/attest.go:38`
- **Problem:**
  1. `probeEnvironment.addresses` did not fail closed when `len(known.node) == 0` after filtering `interfaces()` for global-unicast IPv4 addresses, allowing a probe peer whose source or destination was the node's own IPv4 address if interface enumeration returned empty or only loopback/link-local/IPv6 addresses.
  2. `readProbeAgentConfig` called `os.Open(path)` followed by `f.Stat()`, following symlinks and risking a blocking open on a FIFO.
  3. When `challengeProbe` refused a configured `probe_peer` at challenge issuance, `health-challenge.json` omitted `"probe"` without recording that a configured probe was refused, leaving `health-challenge.json`, `journal.db`, local health details, and `ObservationReport` indistinguishable from an unconfigured probe.
- **Resolution (`#168`, `#171`):** In `#168`, `probeEnvironment.addresses` refuses an empty filtered global-unicast IPv4 list with `node_addresses_unavailable`; `readProbeAgentConfig` checks `os.Lstat` regular mode before opening with `O_NOFOLLOW|O_NONBLOCK` and verifies `os.SameFile(lst, st)` (refusing with `agent_config_unavailable`); and a refused configured probe writes `probe_omitted {peer_id, reason}` into `health-challenge.json` (mutually exclusive with `probe`, included in `Same`), commits `probe_omission/<txn_id>/<nonce>` in SQLite `meta` and `txn_events.detail` (`Journal.ProbeOmissions`) before challenge publication, and includes `probe_omitted` in local `health_attest` diagnostics (`healthattest.ReadChallenge` keeps `DisallowUnknownFields`, creating a one-time compatibility boundary for pre-`#168` agents). In `#171`, `fvpn-agent` (`node/agent/probeexc.go`, `node/agent/attest.go`) surfaces `ObservationReport.checks[name=tunnel_probe].detail = "probe_omitted: <reason>"` (bounded, no peer ID or address, retained across sidecar removal/consumption until a later probe/omission challenge), keeps `tunnel_probe` `not_run` and `data_health` `unknown` with forwarding closed, and answers `health-attest.json` with the existing accepted reason token `"probe refused"`. Adopted proofs: `TestReviewR12_Q6_EmptyInterfaceListAndSymlinkAgentConfig` in `node/updater/followup11_review_test.go` and `node/agent/probe_omission_test.go`.

#### `H-3` — Pre-result heartbeat seeding cross-job misattribution, partial mutation on unexpected `last_good`, and pre-intent `attempt_release_id` poisoning (`closed (#167)`)

- **Where:** `internal/fleetupdate/serving.go:121-150`, `internal/fleetupdate/intent.go:168`, `internal/fleetupdate/results.go:178-183`
- **Problem:**
  1. `observeTx` ignored the caller's validated `jobID` (`r.Update.JobId`) and evaluated `targetRelease` and `auditUnexpectedRelease` against `*n.job` (`fleet_node_state.current_job_id`), misattributing cross-job audits and seeding when a heartbeat bound to an older job arrived after a newer job was queued.
  2. `observeTx` updated `nodes.current_release_id` when `expected(o.CurrentReleaseID)` held even if `o.LastGoodReleaseID` was unexpected or disagreed with `n.lastGood`.
  3. `observeTx` allowed `j.releaseID` (`targetRelease`) to seed `nodes.current_release_id` even when `j.issued == nil` (before `NodeUpdateIntent` had ever issued the job), causing the first `NodeUpdateIntent` call to snapshot `targetRelease` into `attempt_release_id` in `update_jobs.observed_evidence` and causing `SubmitResult` to reject a legitimate pre-switch failure (`stage = "download"`, `current_release_id = boot`) with `422 VALIDATION_FAILED`.
- **Resolution (`#167`):** `observeTx` (`internal/fleetupdate/serving.go`, `docs/updates/central-lifecycle.md`) now resolves `effectiveJob := jobID` (falling back to `n.job` only for the legacy sequence adapter when `jobID == nil`), allows `targetRelease = &j.releaseID` only when `n.job != nil && equalID(effectiveJob, n.job) && equalID(j.incarnation, &i.IncarnationID) && j.issued != nil`, passes `*effectiveJob` to `auditUnexpectedRelease`, and requires `equalID(n.lastGood, o.LastGoodReleaseID)` before any pre-result write to `nodes.current_release_id`. Adopted proofs: `TestReviewR12_Q7_CrossJobAuditAndSeedingMisattribution` and `TestReviewR12_Q7_PreIntentTargetSeedPoisonsAttemptRelease` in `internal/fleetupdate/followup8_review_integration_test.go`.

### Medium Findings

#### `M-1` — Control body validation above `1 MiB` accepted non-`canonjson` tokens and ignored `json.Unmarshal` errors before `matchingIdentity` (`closed (#169)`)

- **Where:** `internal/httpapi/middleware.go:419-436`, `internal/httpapi/middleware.go:505-530`
- **Problem:** For bodies in `(canonjson.MaxBytes, limit]` (`1 MiB < len <= 8 MiB` on `SubmitUsageBatch`), `checkJSONDocument` fell back to `json.NewDecoder.Decode(&doc)` into `json.RawMessage`, which did not reject duplicate object keys, invalid UTF-8 bytes, lone UTF-16 surrogates, nesting above 256, or integers outside `±(2^53-1)` with `400 MALFORMED_REQUEST`. Additionally, `_ = json.Unmarshal(raw, &body)` before `matchingIdentity` ignored unmarshal errors.
- **Resolution (`#169`):** Added `internal/httpapi/jsondoc.go` (`checkLargeJSONDocument`), a streaming token/syntax walk for bodies in `(1 MiB, limit]` enforcing the full `canonjson` ruleset (valid UTF-8, no BOM, no unescaped control chars/NUL, no lone UTF-16 surrogates, no duplicate object keys at any level after unescaping, max depth `256`, integers within `±(2^53-1)` with no fraction/exponent/leading zero/`-0`, and no trailing data), and returned `400 MALFORMED_REQUEST` if `json.Unmarshal` fails before `matchingIdentity`. Adopted proof: `TestReviewR12_Q5_AboveCanonMaxBytesAcceptsDuplicateKeysAndInvalidUTF8` in `internal/httpapi/followup17_review_test.go`.

#### `M-2` — Single IPv6 `/48` allocation exhausted the shared `ingress` rate-limit table on public and mTLS listeners (`closed (#169)`)

- **Where:** `internal/httpapi/middleware.go:183-211`, `internal/httpapi/middleware.go:255-256`, `internal/httpapi/middleware.go:309`, `internal/httpapi/middleware.go:344-354`
- **Problem:** `ingress` shared a single `10,000`-entry map across all classes, unauthenticated `anonymous` requests inserted two keys per peer into `ingress`, `ingress.allow` ran before mTLS client-certificate verification on the agent listener, and capacity eviction scanned the map linearly and only evicted entries idle `> 1h`. Consequently, 5,000 `/64` prefixes from one IPv6 `/48` on `/api/v1/agent/enroll` (or 2,500 unauthenticated `/64`s across 4 mTLS classes) filled `ingress` and locked out all new client addresses for 1 hour.
- **Resolution (`#169`):** Partitioned pre-auth address limiters into per-class `ingress[class]` tables (`browser`, `agent`, `heartbeat`, `lease`, `usage`, `anonymous`), gave `anonymous` its own class table (`anonClass`) separate from authenticated subjects (`subjects`), moved `AuthenticateAgent` (`r.TLS` client certificate check) ahead of `ingress` on the mTLS listener so unauthenticated `401` requests touch no limiter table, and replaced the linear scan with an O(1) intrusive-LRU doubly linked list that evicts the least-recently-updated bucket when idle at full tokens or idle `> 1h`. Adopted proof: `TestReviewR12_Q4_IPv6Slash48ExhaustsSharedIngressTable` in `internal/httpapi/followup17_review_test.go`.

#### `M-3` — `Samples` emitted zero-metadata samples for revoked devices and `Apply` dropped counters on `ConntrackDeleteError` (`closed (#172)`)

- **Where:** `node/enforce/apply.go:120-137`, `node/enforce/apply.go:316-346`
- **Problem:** `Samples(m, rs.Counters)` did not check whether a counter's device UUID was still present in `m.Bindings` (or had a valid `MemberID` and nonzero `BindingRevision`), emitting 4 zero-metadata `Sample` records per revoked device on every subsequent `Apply`. In addition, `Apply` ran `deleteConntrack` before populating `verified.Counters` and `verified.Samples` and aborted `m.Revoke` on the first `conntrack -D` error, returning empty `Counters` and `Samples` on `ConntrackDeleteError`.
- **Resolution (`#172`):** `Samples` now skips counters whose device is not in `m.Bindings` or has `MemberID == uuid.Nil` or `BindingRevision == 0`; `Apply` populates `verified.Counters` and `verified.Samples` before the revoke loop and attempts `deleteConntrack` for every address in `m.Revoke` before returning `*ConntrackDeleteError{Pending}`. Adopted proof: `TestReviewR12_Q2_RevokedDeviceCountersLeakIntoSamplesAndConntrackDropsCounters` in `node/enforce/followup7_review_test.go`.

Adopted proof: `TestReviewR12_Q3_ServingWithoutProbeOmitsSNATFromHostV4` in `node/enforce/followup7_review_test.go`.
