### (a) Boot budgets: environmental exposure; deadline proofs need repair

Code references in this diagnosis name revision `466f1510` unless explicitly marked otherwise. The pre-delivery baseline is `b921c75f`. Product Boot has a 10 s local budget (`node/agent/engine.go:449,466–501`). Boot publishes startup heartbeat, loads SQLite runtime state, starts/polls recovery, captures restart bindings, attempts adoption, establishes Baseline and publishes its heartbeat before setting bootSafe; only then does it open/reconcile usage and settle retained bytes (`engine.go:503–603`). These waits include synchronous disk reads/writes/fsync, local enforcement, and usage restore HTTP, not merely child startup.

`recoverOnce` (`node/agent/updaterecover.go:29–99`, unchanged from `b921c75f`) runs `cmd.Run` in a goroutine and selects on child completion, the local deadline, or `recoverFastWait=250ms`. Boot does not synchronously wait for full child initialization. D155's helper execs the test binary (`node/agent/followup49_transaction_test.go:196–212`); R29's helper is a shell script (`node/agent/review_r29_test.go:225–241`). On their normal waiting paths, the child needs a checkpoint/attestation that is written later, so the 250 ms fast-path wait consumes much of the old 600 ms test allowance. Early child failure is a separate path; “always exactly 250 ms” is not a universal assertion.

Relevant later stages: `captureRestartBindings` is `node/agent/restart_usage.go:76–119`; usage initialization is `node/agent/usage.go:130–221`; `answerHealthOnBoot` is `node/agent/attest.go:86–96`, with attestation write at `attest.go:166`. The 30 s value in the R29 fixture is the signed challenge TTL. The helper actually loops 40 × sleep 0.05, nominally 2 s. The delivered 10 s Boot bound therefore does not establish its claimed 10 < 15 argument. Repair must ensure the helper cannot finish merely because Boot has not yet produced the attestation.

R22's old 80 ms allowance races the pre-bootSafe filesystem work; no recovery child is configured. A pre-canceled caller should return context.Canceled only after Baseline has been established, even when ledger work subsequently exceeds the independent local deadline. The delivered R21/R22 `b.cancel()` workaround instead produces context.Canceled in the local context. It does not preserve expiry semantics. The fix must use actual deadline expiry, prove that the source stage was reached before it, and retain the original normal-TERM and heartbeat assertions. The separate intentional pre-baseline timeout tests remain deadline tests.

### (b) Restart checkpoint: demonstrated product boundary, CI clock remainder not recorded

At `b921c75f`, `CheckpointForRestart` shares the ordinary-sample plan: unchanged readings at `now <= LastSample` inside one interval return ErrHold, whereas FinalSample can close the unchanged epoch. Close subsequently falls back through `shutdownUsage`/handoff (`466f1510:node/agent/usage.go:547–562`); CheckpointForRestart itself neither opened nor closed an epoch. The fallback replaces forwarding with Baseline and closes through FinalSample when that succeeds. Later bytes in the artificial restart gap can then lose the clean adoption context.

The R23 fixture explicitly uses `Now: r.clock.Wall` (`466f1510:node/agent/review_r23_test.go:237`), resets a counter and samples at :251, closes at :265, introduces new traffic at :268, and boots the successor at :280 before its :285 assertion. The discovered boundary reproduces the refusal deterministically; the failed CI logs do not record each clock's nanosecond remainder, so they do not establish this as the measured cause of every historical occurrence. There is no measured occurrence probability or uniform-clock assumption.

The historical `-count=1500 -failfast` attempt failed in 121.214 s with the adoption signature and interval end `2026-11-04 19:39:55.021658 +0000 UTC`; iteration number is not recorded in the non-verbose output. Both added exact-microsecond pre-fix proofs failed (meter package 0.023 s; agent package 0.290 s), although that command's `|| true` masked the process failures. Keep those failures separate from a successful outer shell status.

It leaves epoch, counters and sample timestamp unchanged, and does not mint a delta. `switchEpoch` is `node/agent/meterreset.go:311–332`. Production `ensureUsage` still omits a supplied meter Now (`usage.go:190–194`), so meter defaults to the real wall clock.
