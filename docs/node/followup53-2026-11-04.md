#### 2. Verification of the Orchestrator's Reading for (a)

The orchestrator's reading (*"Boot waits for the recover child, and the child's start-up is a full exec of the test binary. On a loaded runner, that alone can take longer than 600 ms"*) is **confirmed in verdict (test-environment budget cause), with a precision correction on the mechanism**:

### (b) `R23-H-1b` Same-Boot Adoption Is Refused (`review_r23_test.go:277`, `followup40_test.go:125`)

#### 1. Which Check Refuses Adoption and Which Input Differs Between Pass and Fail (`file:line`)

- **Refusing check:** On the successor engine's `next.Boot(t.Context())` (`node/agent/review_r23_test.go:272`), `e.adoptStoredServing(ctx, previous)` (`node/agent/restart.go:25`) checks:
  ```go
  if !beat.Serving || !beat.BaselineOK || beat.BootID != e.bootID || beat.Generation != e.appliedGen {
      return false
  }
  ```
  It returns `false` because `beat.Serving` on disk is `false`.
- **Why `beat.Serving` is `false`:** During the predecessor's `r.eng.Close()` (`node/agent/review_r23_test.go:257`), `e.shutdownUsage(ctx)` (`node/agent/usage.go:552-563`) calls `e.preserveServingOnStop(ctx)` (`node/agent/restart.go:174-195`), which at **`node/agent/restart.go:190`** calls:
  ```go
  if err := e.meter.CheckpointForRestart(ctx); err != nil {
      return false
  }
  ```
  When `CheckpointForRestart` returns `meter.ErrHold`, `preserveServingOnStop` returns `false`, and `shutdownUsage` (`node/agent/usage.go:553-562`) falls back to `e.handoff(ctx)` (`Baseline` + `FinalSample`) and calls `e.beat()` (`usage.go:561`), overwriting the heartbeat on disk with `Serving: false, Generation: 2` and closing epoch `E2` before `src1.setCounter(upB, {Packets: 2, Bytes: 4096})` at `review_r23_test.go:260`.
- **Which input differs between a pass and a fail:** **Wall-clock sub-microsecond nanosecond alignment (`T0.Nanosecond() % 1000 == 0`, exact probability `1/1000` per test run).**
  1. In `r23H1b` (`node/agent/review_r23_test.go:176`), `r := newRig(t)` (`node/agent/engine_test.go:149`) initializes the manual clock from the real wall clock: `clock := timeanchor.NewManual(time.Now().UTC(), time.Hour)` (`T0`).
  2. At `review_r23_test.go:226` and `:241`, `r.clock.Advance(2 * time.Second)` advances `r.clock.Wall()` by exact integer seconds to `T0 + 4s`, preserving the sub-microsecond remainder `T0.Nanosecond() % 1000` (`0..999` ns).
  3. At `review_r23_test.go:243`, `r.eng.meter.Sample(t.Context())` executes `planSwitch` (`node/internal/meter/delta.go:374-429`), which calls `eventInterval(head.LastSample, end)` (`node/internal/meter/delta.go:155-165,390`). `eventInterval` truncates `end` to microseconds (`(T0 + 4s).UTC().Truncate(time.Microsecond)`) and persists `head.LastSample = (T0 + 4s).Truncate(time.Microsecond)` (`delta.go:428`, `node/internal/usagestore/store.go:548,750`).
  4. At `review_r23_test.go:257`, `r.eng.Close()` is called **without advancing `r.clock` after `:243`**.
  5. Inside `r.eng.Close()` -> `CheckpointForRestart(ctx)` (`node/internal/meter/meter.go:362-364`) -> `m.pausedSample(ctx, false)` (`:382`) -> `m.sample(ctx, false)` (`:244`) -> `planSample(head, obs, m.nowUTC(), m.interval, false)` (`node/internal/meter/delta.go:243-276`):
     - `now` is `r.clock.Wall().UTC() = T0 + 4s`.
     - `head.LastSample` is `(T0 + 4s).Truncate(time.Microsecond)`.
     - In **`999/1000` runs** (`T0.Nanosecond() % 1000 != 0`), `now` is `1..999 ns` after `head.LastSample`, so `!now.After(head.LastSample)` at `node/internal/meter/delta.go:260` is `false`, `eventInterval` advances `end` by `+1µs`, `CheckpointForRestart` succeeds, and `preserveServingOnStop` returns `true`.

#### 2. Can a Real Same-Boot Restart Lose Adoption the Same Way, and What Bounds It in Production?

- **Yes (`node/agent/restart.go:190`, `node/internal/meter/meter.go:362-383`, `node/internal/meter/delta.go:260-275`).** On a real node, `CheckpointForRestart` returns `ErrHold` during `Close()` -> `preserveServingOnStop` whenever `!now.After(head.LastSample)` and `head.LastSample.Sub(now) <= interval` while `sameReadings(head.Counters, cur)` is `true`. This can occur on a real node if:
  1. Two samples execute within the same microsecond (or consecutive microseconds) right before `Close()` — for example, `enforce` (`node/agent/engine.go:1459-1460`) calls `e.resumeSampling()` (waking `Meter.Run` at `node/internal/meter/meter.go:451,462`) and `e.switchEpoch(ctx)` (`node/agent/restart.go:205`), where each `eventInterval` call (`node/internal/meter/delta.go:161-163`) advances `head.LastSample` by `+1µs` when `!end.After(start)`, pushing `head.LastSample` up to or `+1µs` ahead of `now`; or
  2. NTP slews or steps the wall clock backward by `<= timeanchor.DefaultBackwardSkew` (`2s`, `node/internal/timeanchor/anchor.go:13`) after `head.LastSample` while zero new packets arrived (`Decide(e.input()).Serve` at `restart.go:187` remains `true` within the `2s` backward-skew window).
  In addition, `Engine.ensureUsage` (`node/agent/usage.go:190-194`) constructed `meter.NewContext` without wiring `Now: e.clock.Wall`.
- **Production bound:** In production, when `preserveServingOnStop` returns `false`, `shutdownUsage` (`node/agent/usage.go:552-562`) runs `e.handoff(ctx)` (`Baseline` + `FinalSample`), where `FinalSample` (`final = true`) succeeds at `node/internal/meter/delta.go:265` with zero lost bytes and writes `beat.Serving = false`. The successor process boots fail-closed on `Baseline` and re-establishes serving on its first `Step` (`enforce` -> `Apply`, bounded by one startup `Step` pass).

### 2.2 Every Condition Under Which a Stale-Lease Report Can Currently Reach Central With Both Exact Dependent Details

A stale-lease `ObservationReport` produced by `Engine.report()` (`node/agent/observe.go:108-184`) reaches Central with **both** exact dependent details (`qos.Detail == "Rate policy could not be applied."` and `source_binding.Detail == "No member binding was admitted."`) if and only if all four of the following conditions hold simultaneously:

1. **Populated published desired state (`evaluateServing == true`, `node/agent/decide.go:272`):**
   `in.Desired != nil && in.Desired.PublicationIntent == api.PublicationIntentPublished && in.DesiredOK && len(in.Desired.DeviceBindings) > 0`.
   *(Note: if `len(in.Desired.DeviceBindings) == 0`, as in the unpopulated bootstrap hold report `01a1a740-94ce-717e-a23f-ad38926b3e5e` in `docs/e2e/at/isolation/generation-holds-central.json`, `evaluateServing` is `false`, so `lease`, `qos`, and `source_binding` have `Status == "not_run"` at `decide.go:336-338`; Central classifies that zero-member hold as `"stale_generation"` via `d.Errors` having `stage="lease", code="STALE_GENERATION"`, not via failed `qos`/`source_binding` checks.)*
2. **Generation mismatch (`leaseGenerationStale(in) == true`, `node/agent/decide.go:569-578`):**
   `in.Lease != nil && uint64(in.Desired.ConfigGeneration) != 0 && uint64(in.Lease.ConfigGeneration) != uint64(in.Desired.ConfigGeneration)`.
3. **No retained enforcement or preflight dependency failure (`node/agent/decide.go:360`):**
   `in.ApplyError == nil && !in.DependencyMissing` (otherwise `D-126` at `decide.go:360-371` replaces `lease`, `qos`, and `source_binding` with `Detail == nil` and `ErrorCode == code`).
4. **No prior serving `Apply` or `verifyServingModel` in the current `Engine` process (`e.servingRead == nil`, `node/agent/serving_evidence.go:41-44`):**
   Because `e.retainServingRead` (`serving_evidence.go:22-25`) sets `e.servingRead` on every `e.plane.Apply` (`engine.go:1334`) and every `e.verifyServingModel` (`serving.go:51`) and nothing in `node/agent/` ever clears `e.servingRead`, `e.servingRead` is `nil` **if and only if the current `Engine` process has never executed `e.plane.Apply` or `e.verifyServingModel` since `New()`**.

Why even that condition cannot yield a `"stale_generation"` classification on a populated hold in the current codebase:

- **Continuous process that served generation $G$ before holding on $G+1$:** Cannot satisfy condition 4 (`e.servingRead` is guaranteed non-nil from generation $G$), so `qos.Detail` is always overwritten with `"read_at=..."` and Central returns `"check_failed"` (e.g., reports `01a1a744-4f5d-7641-a9fd-30001016649f` through `01a1a744-6271-7e13-bc6f-b584dc713e09` in `docs/e2e/at/isolation/generation-holds-central.json`).
- **Restarted `Engine` process during an active populated hold while `/leases:renew` is held:** Satisfies conditions 1–4 (`e.servingRead == nil`), so its reports **do** reach Central with both exact details (`qos.Detail == "Rate policy could not be applied."` and `source_binding.Detail == "No member binding was admitted."`), as seen on post-restart reports `01a1a744-695b-7de3-8109-5720975a81d9` (Attempt 1) and `01a1a745-f291-7bb7-935e-dc4a6aa736de`..`01a1a745-fe4c-79bd-94f1-ffc11f7ba1d6` (Attempt 3) in `docs/e2e/at/isolation/generation-holds-central.json`. **However**, on restart `loadState` (`node/agent/engine.go:540,545,568`) initializes `e.leaseFresh = false`, `adoptStoredServing` (`node/agent/restart.go:21,50`) refuses adoption because `e.desired.ConfigGeneration != e.lease.ConfigGeneration`, and while the proxy withholds `/leases:renew` no HTTP 200 reaches `acceptLease` (`node/agent/sync.go:336,351`). With `in.LeaseFresh == false`, `safetyOf` (`node/agent/decide.go:483,505-507`) sets `rep.SafetyStatus = api.SafetyStatusExpired` (`"expired"`), which fails `internal/nodes/generation_hold.go:83-85` (`r.SafetyStatus != api.SafetyStatusPassed`) and classifies the post-restart reports as `"isolation_unconfirmed"`.
- Consequently, the **only** scenario in which the current code could both emit the two exact dependent details on a populated stale-lease hold **and** classify as `"stale_generation"` (`SafetyStatus == "passed"`) is if a newly started `Engine` process that has never entered `Serve` (`e.servingRead == nil`) actively receives an HTTP 200 response from `/leases:renew` (`acceptLease` setting `e.leaseFresh = true` and `e.leaseMono > 0`) carrying a valid signed lease whose `config_generation` is still behind the node's desired `config_generation`.

## 3. Devstack F31-01: Live Source-Binding Verification Design

### 3.1 What a Genuine Live Source-Binding Check Verifies

In the current codebase (`node/agent/decide.go:211-245,357-371`), `bindingOK` is a purely in-memory boolean derived from `buildModel(in)` (`decide.go:589-695`): it starts `true`, becomes `false` only when `buildModel` fails capacity/address validation or when `len(in.Desired.DeviceBindings) > 0 && len(model.Bindings) == 0`, and in every false path `qosOK` is also set `false`. Meanwhile, live kernel checks that touch source addresses or member routing are currently folded into `e.applyError` via `e.noteApply(err)` (`node/agent/engine.go:1493-1513`), where `D-126` (`decide.go:360-371`) stamps the same code onto `lease`, `qos`, and `source_binding` together (`docs/e2e/runs/2026-11-03/followup31/source-binding.md:16-70`).

A genuine live source-binding verifier separates **source-address admission and member-ingress route binding** from `qos` (HTB classes/rates and `tc` filters) and from `lease` (signed lease freshness/generation), using kernel state the agent already reads across two layers:

1. **Layer A — Live `nftables` source-binding state while serving (`e.serving == true`):**
   From `nft -j list ruleset` (`node/enforce/verify_tc.go:144`) and `nft list set inet fvpn allowed_v4` (`node/enforce/deadline_read.go:152`), already read inside `enforce.VerifyServing` (`node/enforce/verify_tc.go:124-177`) and `servingPresenceExecutor` (`node/agent/allowed_presence.go:15-94`):
   - **`@allowed_v4` set membership and bounded lifetimes (`node/enforce/verify.go:104,132-137`, `node/enforce/deadline_read.go:112-145`, `node/agent/allowed_presence.go:43-94`):**
     Every admitted binding's `/32` `AllowedV4` address whose remaining window exceeds `DeadlineInstallBound + DeadlineGranularity` (`101 ms`, `node/enforce/model.go:91,97`) must be present in `table inet fvpn` set `allowed_v4` (`allowed_presence.go:86-90`), every element in `allowed_v4` must be a timed `/32` host address belonging to an admitted binding in `m.Bindings` with `timeout <= original` and `expires <= remaining` (`deadline_read.go:138-143`), and `rs.Tainted["allowed_v4"]` must be `false` (`verify.go:132-137`).
   - **Per-device source-address binding on forward rules (`node/enforce/verify.go:67-90,704-745,822-858`):**
     In chain `forward`, every admitted device `d.Binding.DeviceID` must have upload (`u_<device_id>`, `nu_<device_id>`) and download (`d_<device_id>`, `nd_<device_id>`) rules bound to `m.Datapath.MemberIngress` and `m.Datapath.Uplink` whose host-side `/32` address (`rule.Saddrs` for upload, `rule.Daddrs` for download, inspected by `deviceHostSide` at `verify.go:849-858`) is a single `/32` in `d.Addrs`, placed strictly after the `ip saddr != @allowed_v4 drop` and `ip daddr != @allowed_v4 drop` guards (`checkForwardOrder` at `verify.go:656-691`).
     *(Note: in `verifyDeviceClass` at `verify.go:837-844`, a missing/mismatched `d.Addrs` host address is currently misclassified as `ReasonQoS` alongside a wrong `rule.Prios` HTB class ID; splitting address mismatch from `rule.Prios` mismatch attributes source-address rule drift to source binding while keeping HTB class drift on `ReasonQoS`.)*
2. **Layer B — Live member-ingress interface and per-binding source-route state (both while serving and during `auditBlocked` holds when `e.appliedModel != nil`):**
   From the namespace link and routing tables already read by `SystemPlane.MemberPath` (`node/agent/memberpath.go:37-119`):
   - **Member-ingress link and retained address state (`node/agent/memberpath.go:55-69,103-110`):**
     `<MemberIngress>` (`fvmb0` in e2e/devstack, `fv-fh` in netlab) exists, carries flag `UP`, has a non-tentative IPv4 address, and matches all retained `e.memberPath.Addresses` hashes.
   - **Per-binding overlay source-address route binding (`node/agent/memberpath.go:79-102,112-116`):**
     For every binding in the active or retained applied model (`m.Bindings`, where `m` is `*e.appliedModel`) and every `/32` (or `/128`) prefix in `binding.AllowedV4` (and `binding.AllowedV6`), the kernel routing table resolves that member device address to a unicast route on `dev == m.Datapath.MemberIngress` with no `linkdown` flag and matches the retained `e.memberPath.Routes` hashes.
   - **Why Layer B is essential for `F31-01` during a populated generation hold:**
     While a node is in a populated stale-lease hold (`d.Serve == false`), the fail-closed baseline (`VerifyBaseline` at `node/enforce/verify.go:141-201`) intentionally keeps `@allowed_v4` empty (`verify.go:172-174`). Running Layer B's per-binding route/interface check against `e.appliedModel.Bindings` inside `auditBlocked` (`node/agent/serving.go:208-236`) verifies that every retained member binding's `/32` overlay address remains bound to `<MemberIngress>` during the hold, detects if a member's `/32` route on `<MemberIngress>` is deleted or diverted to another interface, and detects restoration when the route on `<MemberIngress>` is restored — without requiring `@allowed_v4` to be open during the hold.

### 3.3 Cost and Cadence (`<= 150 ms` `D-085` Budget)

- **Existing per-step read budget:**
  `verifyServingModel` (`node/agent/serving.go:40-59`) and `auditBlocked` (`node/agent/serving.go:208-236`) run once per step (`stepInterval()` = `1s–10s`, `servingReadTimeout()` = `500 ms` at `serving.go:36-38`) and must stay within the `<= 150 ms` `D-085` verification budget (`node/agent/followup21_netlab_test.go:165-190`).
- **Zero extra `nft` or `tc` subprocess calls:**
  All Layer A (`nftables`) source-binding checks (`@allowed_v4` element presence/lifetimes in `node/agent/allowed_presence.go:43-94` and `node/enforce/deadline_read.go:112-145`, plus per-device `u_<id>`/`d_<id>` source-IP checks in `node/enforce/verify.go:822-858`) reuse the **existing** `nft -j list ruleset` (`node/enforce/verify_tc.go:144`) and `nft list set inet fvpn allowed_v4` (`node/enforce/deadline_read.go:152`) outputs already captured during `enforce.VerifyServing`. This adds **0 subprocess calls** and `< 0.1 ms` of in-memory evaluation.
- **Replacing $O(N)$ `ip route get` subprocesses with bounded batch read + in-memory LPM:**
  `SystemPlane.MemberPath` (`node/agent/memberpath.go:55,81,98`) currently runs `ip -j addr show dev <iface>`, `ip -j -4 route show table all dev <iface>`, `ip -j -6 route show table all dev <iface>`, and then loops `ip -j route get <addr>` once per bound address (`2N + 3` subprocesses).
  By evaluating per-binding route resolution in memory via longest-prefix match over the already-fetched `-j -4 route show table all` and `-j -6 route show table all` JSON tables (checking that the winning route for each `binding.AllowedV4` / `AllowedV6` prefix has `dev == m.Datapath.MemberIngress`, `type == "unicast"`, and no `linkdown` flag), Layer B uses a **constant 3 `ip -j` subprocess calls** (`addr show dev <iface>`, `-4 route show table all`, `-6 route show table all`, `~2–4 ms` total in netlab regardless of binding count), keeping total `VerifyServing` + source-binding verification at `~15–25 ms` (well inside the `<= 150 ms` `D-085` bound).
