# Portal Live Stack Operations & D-050 Product Seeding (`OPERATIONS.md`)

`apps/portal/e2e/dev-stack.mjs` runs `fvpn-control` and `fvpn-worker` against an isolated PostgreSQL database (`$FVPN_TEST_DATABASE_URL`) and exercises real control-plane and agent APIs:

- **Member groups (D-057):** Creates `standard-exits` and `default-members` through `POST /api/v1/admin/groups` (`create-member-groups-via-api`), retiring the raw `INSERT INTO member_groups` seed.
- **Member identity & device discovery (D-052):** Fake NetBird serves users and peers matching the dev OIDC subject (`is_service_user: false`, `is_blocked: false`); `fvpn-worker` runs `IdentityDiscovery` (`mapping_proof = shared_issuer_public_subject:<issuer>`) and projects `member_devices` and `device_authorization_observations`.
- **Two enrolled fake agent reporters, exit publication & update batch results (D-048, D-050, D-056, D-057, D-058, SECOPS-11):**
  1. Issues an enrollment token via `POST /api/v1/admin/enrollments` and enrolls the primary active node (`tw-tpe-01` / `tw-tpe`, `amd64`, NetBird peer `nb-peer-node-1`) via `POST /api/v1/agent/enroll`. Its fake agent test double (which makes no kernel enforcement claims) fetches `GET /api/v1/agent/desired-state` over mTLS to read the compiled `config_generation` and `dns.resolver_document` reference (published by `fvpn-worker`'s `dns.publish` job after activating `dns_profile` via `POST /api/v1/admin/policies/{definition_id}/activate`) and submits `ObservationReport` payloads with `applied_config_generation` matching the fetched desired state, `member_forwarding_enabled: true`, `provisioning_state: "ready"`, `data_health: "healthy"`, `safety_status: "passed"`, a valid UUID `lease.lease_id` and finite future `lease.expires_at`, `checks` (`internet_only`, `meter_path`, `tunnel_probe`, `lease`, `qos`, `source_binding` all `"passed"` with `NodeCheck.detail`), and typed `dns_policy_evidence`.
  2. Issues a second enrollment token via `POST /api/v1/admin/enrollments` and enrolls the secondary node (`jp-tyo-01` / `jp-tyo`, `arm64`, NetBird peer `nb-peer-node-2`) via `POST /api/v1/agent/enroll` with its own mTLS identity and reporter, retiring the `SEEDED_NODE_2_ID` raw SQL inserts (`nodes`, `node_incarnations`, `exits`). It stays offline (`waiting_online`, `unconfirmed: true`, `policy_generation: null`, `policy_refs: null`, `dns_policy_evidence: null`) by not submitting observations.
  3. Publishes the primary exit and attaches `group_ids` via `PUT /api/v1/admin/nodes/{node_id}/publication` under `If-Match`, confirms armed forwarding evidence at the new desired-state generation via `POST /api/v1/agent/observations` (`PublicationForwardingEvidence`, SECOPS-11), and lets `fvpn-worker` execute `PublishExit` + `ReadExitState` against fake NetBird until `exits.publication_observed = 'active'`, retiring the raw `UPDATE exits` seed.
  4. Creates the fleet update batch via `POST /api/v1/admin/update-batches` (`scope: 'all_nodes'`), pulls the signed desired-state envelope and update intent via mTLS `GET /api/v1/agent/desired-state`, delivers the signed-hash update result via mTLS `POST /api/v1/agent/update-results` (`state: 'succeeded'`, `policy_generation` matching the compiled desired-state generation), confirms via `POST /api/v1/agent/observations`, and polls `GET /api/v1/admin/update-batches/{batch_id}`.

## Remaining D-050 Fixture Seeds

All member groups (`member_groups`), node enrollments (`nodes`, `node_incarnations`, `exits`), exit publication projections (`exits.publication_intent`, `exits.publication_observed`, `exit_groups`), member entitlements, device authorizations, and fleet update batches/targets/jobs are now driven through product HTTP APIs and `fvpn-worker` projectors. Only catalog/bootstrap inputs without public admin creation endpoints (`releases` + `artifacts` + `release_verifications` + `fleet_config` bootstrap, initial `policy_definitions`/`policy_revisions`, `plans`/`plan_revisions`, `billing_customers`, and the `> 2^53` `usage_rollups` precision row) are seeded in SQL.
